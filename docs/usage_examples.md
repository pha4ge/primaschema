# Usage Examples

Every example below is a working invocation.

Every parameter is reachable under two names: a short form with the
`primer_scheme_` prefix dropped, and the full field name. `--derived-from` and
`--primer-scheme-derived-from` are the same flag, as are `--email` and
`--primer-scheme-contributor-email`. The examples use the short form.

## create

Create a new primer scheme from an existing `primer.bed` and `reference.fasta`.
Contributors, target organisms and vendors are passed as `key=value` pairs; the
keys are the model field names with their `primer_scheme_*` prefix dropped.

```bash
primaschema create \
    --name example-scheme \
    --amplicon-size 400 \
    --version v1.0.0 \
    --development-status VALIDATED \
    --license CC-BY-SA-4.0 \
    --creation-date 2024-01-15 \
    --contributor "name=Alice Smith,email=alice@example.org,orcid=0000-0001-2345-6789" \
    --target-organism "name=Example organism,ncbi_taxon_id=000001" \
    --bed-path ./example-scheme.primer.bed \
    --reference-path ./example-scheme.reference.fasta \
    --primer-schemes-path ./schemes
```

The scheme is written to `./schemes/example-scheme/400/v1.0.0/`.

`--submission-date` defaults to today if omitted, and `--license` defaults to
`CC-BY-SA-4.0`. `--creation-date` is optional.

Every flag also accepts its full `--primer-scheme-*` spelling, so `--name` and
`--primer-scheme-name` are equivalent.

### Repeatable fields

`--contributor`, `--target-organism` and `--vendor` may be repeated to supply
more than one value:

```bash
primaschema create \
    --name example-scheme \
    --amplicon-size 400 \
    --version v1.0.0 \
    --development-status DRAFT \
    --contributor "name=Alice Smith,email=alice@example.org" \
    --contributor "name=Bob Jones,email=bob@example.org" \
    --target-organism "name=Example organism,ncbi_taxon_id=000001" \
    --vendor "name=ExampleCo Ltd,kit_name=ExamplePanel v1,url=https://example.com" \
    --bed-path ./example-scheme.primer.bed \
    --reference-path ./example-scheme.reference.fasta \
    --primer-schemes-path ./schemes
```

`--application` and `--scope` are repeatable too, and take values from a fixed
list (`--help` shows the choices for each):

```bash
primaschema create \
    ... \
    --application CLINICAL \
    --application WASTEWATER \
    --scope WHOLE-GENOME \
    --scope QPCR
```

### Recording the generator

Pass the tool that produced the scheme as `name:version`:

```bash
primaschema create \
    ... \
    --generator primalscheme:3.0.3
```

## validate

Validate a single scheme:

```bash
primaschema validate ./schemes/example-scheme/400/v1.0.0/info.json
```

Validate all schemes under a directory:

```bash
primaschema validate --all ./schemes
```

Auto-normalise `primer.bed` and `reference.fasta` formatting in place when
hashes differ only by line order:

```bash
primaschema validate --fix ./schemes/example-scheme/400/v1.0.0/info.json
```

Additionally validate against the LinkML schema:

```bash
primaschema validate --additional-linkml ./schemes/example-scheme/400/v1.0.0/info.json
```

### Choosing how much to check

`--checks` selects which files are validated:

| Value | Validates |
| --- | --- |
| `info` | `info.json` alone: the model, path agreement, identifier |
| `core` | `info` plus `primer.bed`, `reference.fasta` and the checksums |
| `full` | `core` plus `README.md` and its agreement with `info.json` (default) |

A scheme fetched with `get` has no `README.md` — that file is generated by
`create` and `rebuild`, and is not downloaded — so validating a freshly
downloaded scheme needs `core`:

```bash
primaschema get example-scheme/400/v1.0.0 --output ./schemes
primaschema validate ./schemes/example-scheme/400/v1.0.0/info.json --checks core
```

Use `info` to check metadata alone, without reading the primer or reference
files:

```bash
primaschema validate ./schemes/example-scheme/400/v1.0.0/info.json --checks info
```

## rebuild

Recompute checksums and regenerate `README.md` for a single scheme:

```bash
primaschema rebuild ./schemes/example-scheme/400/v1.0.0/info.json
```

Rebuild all schemes, also resorting `primer.bed` lines:

```bash
primaschema rebuild --all --reformat-primer-bed ./schemes
```

Resync `name`, `amplicon_size` and `version` from the directory path:

```bash
primaschema rebuild --sync-metadata ./schemes/example-scheme/400/v1.0.0/info.json
```

## index

The output directory must already exist.

Build an `index.json` from a local schemes directory:

```bash
mkdir -p ./dist
primaschema index ./schemes --output-path ./dist
```

Attach a base URL so the index contains direct download links:

```bash
primaschema index ./schemes \
    --base-url https://raw.githubusercontent.com/example-org/primer-schemes/main/schemes \
    --output-path ./dist
```

Update an existing index rather than rebuilding from scratch, and record the
commit the schemes came from:

```bash
primaschema index ./schemes \
    --index-path ./dist/index.json \
    --base-url https://raw.githubusercontent.com/example-org/primer-schemes/main/schemes \
    --source-commit 1a2b3c4 \
    --output-path ./dist
```

Both `index.json` and a gzipped `index.json.gz` are written.

## get

Download a specific scheme by `name/amplicon_size/version`:

```bash
primaschema get example-scheme/400/v1.0.0
```

Download to a specific output directory:

```bash
primaschema get example-scheme/400/v1.0.0 --output ./downloaded-schemes
```

Download all schemes matching a partial identifier:

```bash
primaschema get example-scheme/400 --allow-multiple --output ./downloaded-schemes
```

Download every scheme in the index:

```bash
primaschema get --all --output ./downloaded-schemes
```

Use a local or custom index. The index's `--base-url` must be reachable, since
the scheme files themselves are fetched over HTTP:

```bash
primaschema get example-scheme/400/v1.0.0 --index ./dist/index.json
```

Overwrite an existing output directory:

```bash
primaschema get example-scheme/400/v1.0.0 --output ./downloaded-schemes --force
```

## flatten and unflatten

Flatten an `info.json` into a single-row CSV, for review or bulk editing in a
spreadsheet. Repeated fields are packed into semicolon-delimited cells:

```bash
primaschema flatten ./schemes/example-scheme/400/v1.0.0/info.json \
    --output-path ./scheme.csv
```

Reconstruct an `info.json` from that CSV:

```bash
primaschema unflatten ./scheme.csv --output-path ./info.json
```

## modify

Every `modify` subcommand takes the path to an `info.json` as its first
positional argument and rewrites it in place, regenerating the scheme's
`README.md`.

### add-contributor

Positional `INFO-PATH` then the contributor name, with optional flags:

```bash
primaschema modify add-contributor \
    ./schemes/example-scheme/400/v1.0.0/info.json \
    "Alice Smith" \
    --email alice@example.org \
    --orcid 0000-0001-2345-6789
```

Insert at a specific position (0-based) rather than appending:

```bash
primaschema modify add-contributor \
    ./schemes/example-scheme/400/v1.0.0/info.json \
    "Alice Smith" \
    --idx 0
```

### update-contributor

Replace the contributor at index 0 (positional `INFO-PATH IDX NAME`):

```bash
primaschema modify update-contributor \
    ./schemes/example-scheme/400/v1.0.0/info.json \
    0 \
    "Alice Smith" \
    --email alice.smith@example.org
```

### remove-contributor

Remove the contributor at index 1:

```bash
primaschema modify remove-contributor \
    ./schemes/example-scheme/400/v1.0.0/info.json \
    1
```

### add-vendor

```bash
primaschema modify add-vendor \
    ./schemes/example-scheme/400/v1.0.0/info.json \
    "ExampleCo Ltd" \
    --url https://example.com \
    --kit-name "ExamplePanel v1"
```

### update-vendor

Replace the vendor at index 0 (positional `INFO-PATH IDX NAME`):

```bash
primaschema modify update-vendor \
    ./schemes/example-scheme/400/v1.0.0/info.json \
    0 \
    "ExampleCo Ltd" \
```

```bash
primaschema modify remove-vendor \
```

### update-status


### update-generator

Positional `INFO-PATH` then the generator name, with the version as a flag:

```bash

    ./schemes/example-scheme/400/v1.0.0/info.json \
    primalscheme \
    --version 3.0.3
```
